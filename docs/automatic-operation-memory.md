# 自动操作记忆：设计与验收契约

目标：让浏览器自动化越用越快。日常操作自动产生学习证据，后台沉淀可复用的 `.webmcp`，使用反馈自动触发版本更新和过时清理。前台不等待学习模型。

## 两个循环

```text
前台：任务 → 已有操作/确定性批次 → Jev 选择必要分支 → 执行 → 真实断言
                         │成功/失败回执
后台：采集 → 归一化与参数化 → 候选 → 多次验证 → 发布 → 使用反馈 → 更新/淘汰
```

主模型负责一次规划和未知异常；Jev 负责已知候选间的快速选择。本地运行器复用连接，并将动作、断言和下一次观察合成一次浏览器请求。

## 生命周期

| 状态        | 进入条件                                     | 行为                                                                |
| ----------- | -------------------------------------------- | ------------------------------------------------------------------- |
| candidate   | 可参数化、稳定定位、以实际断言完成的成功操作 | 保存模板、类型和证据计数，不保存输入样本                            |
| active      | 达到最少成功观察次数                         | 自动发布 `.webmcp/learned/auto_*.tool.json`，可通过普通 `call` 使用 |
| quarantined | 定位/契约等结构性失效，或依赖脚本版本改变    | 从活动目录移除，保留诊断；新的成功证据可以生成新版本                |
| retired     | 长期不用、容量淘汰、被新版本替代             | 活动文件删除，旧版本进入本地归档                                    |

成功证据不等于模型口头宣告完成：要求执行成功和明确的 `assert`。首版自动编译确定性 Semantic Shell 片段，不从网页文本自动生成 JavaScript。对不能稳定参数化、只含坐标/ref、包含凭据或任意 JS 的轨迹，记录跳过原因。

## 参数化和适用范围

- 复用实际 DSL 解析器；保留动作顺序、管道和失败传播。
- 变量、填入值、选项值、工具输入编译成类型化参数；持久化模板和 schema，不保存 token/密码/原始输入。
- 首版适用条件绑定精确页面 URL（含普通 query/hash），保守区分业务记录和路由。每次调用前由执行器核对，输入类型和依赖指纹也在执行前核验；含凭据参数的 URL 不自动发布。
- 生成的名称由规范化操作内容确定；相同模板再次成功只更新证据，而不是无限创建新文件。
- 已有 page tool 可以成为依赖，依赖文件内容变化时旧版本失效。

## 自动更新和淘汰

前台回执进入有界队列，后台串行处理同一 workspace。定时维护仅触及由学习器创建并且内容指纹仍匹配的文件。人工改动过的文件进入冲突状态，保留文件与诊断。

清理流程为：写归档和原因 → 更新状态 → 删除指纹匹配的活动文件 → 立即失效工具目录缓存。原始人工 `.webmcp` 不因“时间久”被当作生成垃圾；其版本变化通过依赖指纹触发生成文件重学。

结构性错误与临时错误分开：权限、网络、超时或未知结果首先保留回执，不自动重放业务写入。结构性失效停用旧工具；用户继续正常操作并再次通过断言后，后台自动形成新证据，不需要“生成脚本”指令。

## 速度约束

- 日常浏览器响应不 await 后台学习/磁盘归档/Jev 适用性判断。
- 确定动作零模型调用；一个必要语义分支一次 Jev 请求。
- 连续流程使用常驻进程和本地 HTTP 连接；优先复用动作返回的下一步观察。
- 缓存命中仍执行廉价适用条件/输入检查和业务断言。
- 学习任务异常在管理状态和日志可见；不伪称生成/验证成功。

## 必须验证

1. 普通执行两次经过断言的参数化操作，会自动出现可调用工具。
2. 第三次通过生成工具换输入执行，结果正确。
3. 密钥/密码、旧 ref、失败批次、未验收批次不会被自动发布。
4. 依赖变更/结构性失败会使旧活动文件失效；新成功操作能重新积累证据。
5. 过期生成文件自动归档并从活动目录删除；人工改动和 symlink 边界不会被覆盖。
6. 并发回执、进程重启、后台写入失败不会产生假 active 状态。
7. 对照真实浏览器任务的调用数、Jev 耗时、整段 wall time 和正确率。
